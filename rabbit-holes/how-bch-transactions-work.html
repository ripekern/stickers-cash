How Bitcoin Cash Transactions Actually Work

Let's get technical. This is the deep technical details of how BCH transactions work under the hood.

You've read the overview. Now let's pop the hood and look at the engine. This rabbit hole goes deep into the technical architecture of Bitcoin Cash transactions.

Transaction Structure

Every Bitcoin Cash transaction has three components:

  • Inputs: References to previous transaction outputs (UTXOs) you're spending
  • Outputs: New UTXOs being created, specifying amounts and locking conditions
  • Unlocking scripts: Cryptographic proofs that you have the right to spend the inputs

Unlike a bank account where you have a balance, BCH uses the UTXO model (Unspent Transaction Outputs). Think of it like cash: you don't have a "balance" in your wallet, you have specific bills and coins. When you spend, you hand over specific bills and get change back.

The UTXO Model Explained

When Alice sends Bob 1 BCH, she's not debiting her account. She's creating a transaction that:

  1. Takes one or more of her previous unspent outputs (say, a 2 BCH output she received earlier)
  2. Creates a new 1 BCH output locked to Bob's public key hash
  3. Creates a 0.9999 BCH output locked to her own key (change)
  4. Pays 0.0001 BCH in transaction fees to miners

Each UTXO can only be spent once. The network tracks all unspent outputs in a database called the UTXO set. When a transaction is confirmed, its inputs are removed from the UTXO set and its outputs are added.

Cryptographic Signatures

To spend a UTXO, you must provide:

  • The public key that matches the hash in the locking script
  • A digital signature created with the corresponding private key

The signature proves you control the private key without revealing it. BCH uses Elliptic Curve Digital Signature Algorithm (ECDSA) with the secp256k1 curve.

The signature covers:

  • The transaction hash (all inputs and outputs)
  • The input index being signed
  • The UTXO being spent

This ensures the signature is bound to the specific transaction. If anyone modifies the transaction (changing amounts, outputs, etc.), the signature becomes invalid.

Script System

BCH uses a stack-based scripting language. Each UTXO has a locking script (scriptPubKey) that specifies the conditions to spend it. To spend it, you provide an unlocking script (scriptSig).

The most common locking script is Pay-to-Public-Key-Hash (P2PKH):

OP_DUP OP_HASH160 <pubKeyHash> OP_EQUALVERIFY OP_CHECKSIG

The unlocking script provides:

<signature> <pubKey>

When combined and executed:

  1. Signature and pubKey are pushed to the stack
  2. OP_DUP duplicates the pubKey
  3. OP_HASH160 hashes it
  4. The expected pubKeyHash is pushed
  5. OP_EQUALVERIFY checks they match (fails if not)
  6. OP_CHECKSIG verifies the signature against the transaction

If all operations succeed and the stack has a TRUE value, the spend is valid.

Transaction Validation

When a node receives a transaction, it checks:

  • Syntactic validity: Proper format, no duplicate inputs, outputs > 0
  • Input existence: All referenced UTXOs exist and are unspent
  • Script execution: Unlocking and locking scripts execute successfully
  • No double-spends: Inputs haven't been spent in another confirmed transaction
  • Fee adequacy: Transaction fee is reasonable (inputs - outputs)

If all checks pass, the transaction enters the mempool and waits for miners to include it in a block.

Mining and Consensus

Miners select transactions from their mempool and assemble them into a block. They must solve a proof-of-work puzzle: find a nonce such that the block hash is below the target difficulty.

When a miner finds a valid block:

  1. They broadcast it to the network
  2. Other nodes validate the block (proof-of-work, transactions, etc.)
  3. If valid, nodes add it to their blockchain
  4. The UTXO set is updated (inputs removed, outputs added)

Each additional block built on top increases the transaction's "confirmations." More confirmations = more security against reorganization.

Why This Matters

Understanding the technical details helps you appreciate:

  • Why BCH is trustless: Cryptography replaces trusted third parties
  • Why fees exist: Miners need incentive to include your transaction
  • Why confirmations matter: Each block makes reversal exponentially harder
  • Why self-custody is powerful: You control the keys, you control the funds

The beauty of Bitcoin Cash is that all of this happens without any central authority. The protocol, cryptography, and economic incentives work together to create a system that's secure, censorship-resistant, and open to everyone.
