Tokens on the cash layer

CashTokens add fungible tokens and NFTs to BCH itself — not to a sidechain, not to a separate ledger. The fees are still paid in BCH.

Post 24 of 30 · 3 min read · Oct 22, 2026

Bitcoin Cash has a native token system called CashTokens. It was activated in May 2023, and it does not live on a sidechain or require a bridge. Tokens are validated by the same full nodes that validate BCH, and transaction fees are still paid in BCH.

Two kinds of token

CashTokens adds two primitives. A fungible token is divisible and interchangeable, like a currency or a loyalty point. An NFT is indivisible and carries a commitment, a short piece of data that can represent a receipt, a ticket, a membership, or contract state.

Every token belongs to a category. The category ID is derived from the transaction that created it, which gives the token a unique on-chain identity. The consensus rules enforce supply and transfer behavior, so a wallet or contract can verify that a token is what it claims to be without trusting a central issuer database.

Tokens travel alongside BCH in the same UTXO. A single transaction can move coins, fungible tokens, and an NFT together. That makes the model composable: a contract can require payment in BCH and the transfer of a token in the same spend.

No separate gas token

On many smart contract chains, using an application requires a second asset for gas. On BCH, the fee is just the BCH network fee. A token transfer costs a fraction of a cent in normal conditions, and there is no separate token to acquire before you can use the network.

That is a meaningful UX difference. A community currency, a loyalty program, or a ticket system does not need to teach users two assets. They hold BCH for fees and the token for the application. The wallet can show both, and the transaction can move both at once.

What tokens can represent

The technical primitive is neutral. A fungible token can represent a community currency, a voucher, a share in a project, a loyalty balance, or a stablecoin issued by a trusted party. An NFT can represent a ticket, a membership, a receipt, a collectible, or a piece of state that a contract can read.

CashTokens make the token itself verifiable: the category, the supply, and the transfer rules are enforced by consensus. The issuer’s promise is separate. A voucher is useful because a business honors it; a stablecoin is useful because an issuer redeems it. CashTokens give that promise a transparent, on-chain token. Choose issuers with a track record, and the token layer does the rest.

Use a token-aware wallet

CashTokens are native, and modern BCH wallets support them. A token-aware wallet displays token balances alongside BCH and constructs the right transaction. Use a wallet that shows tokens clearly, and verify what you are signing. The ecosystem already has token-aware wallets, metadata registries, explorers, and contract libraries — and it is growing.

Why native matters

A token system can be built on top of a chain with metadata and indexers. CashTokens takes a different route: put the primitive in consensus. Every full node checks the rules. A contract can inspect token data directly. There is no separate indexer that must be trusted for validity.

That is the BCH pattern again. Keep the core small, but make the core actually enforce the things people need. Tokens are useful. Making them native makes them cheaper, safer, and easier for contracts to use.
